Every screen sits inside the #122 frame and follows #205: next action as the card title, colour only for exceptions. The counter can't read these documents today: GET /counter-work carries only each item's header, so P6 adds a counter read per kind. SPEC.md lists every API change the screens need.

Decided by Shafeek, 20 Nov 2026
  1. Q1 · Short or damaged delivery: “Something doesn't match” sends the line, the problem, the count and a note to the approver through a new endpoint. It appears in their Daily work; they correct and approve again on the web. The same applies to “Can't pick all of it” on a transfer out and on a held delivery.
  2. Q2 · Transfer arrives short: a manager closes the remainder on the web with a reason. “Never left the source” returns the units to the source's stock; “Lost in transit” writes them off. The counter only receives.
  3. Q3 · Stocktake posting: the API changes to apply the difference found at count time: counted − (snapshot + movements up to when that line was counted). Sales and deliveries after the count are kept, and sales made while counting aren't taken off twice. An integration test proves today's behaviour first.
  4. Q4 · Supplier return collection: the signed paper return note is enough for v1. No API change.
  5. Q5 · Import undo: an Imports filter in Counter work lists this branch's imports that still have stock and can still be undone. It needs a counter read: the web's import history isn't open to the counter, and its undo-blocked reason sends exactly these imports to the counter.
